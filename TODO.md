# Agor iOS — Bugs & Feature Requests

## Bugs

- [x] **Agent listening while working** — During agent tool execution/working phase, the app should not be listening for user input. It should transition from "agent working" directly to "speaking about what is doing" (and nothing else) until the agent has finished its task. Fixed: TTS onSpeechFinished now respects isPaused state.
- [x] **Session context mismatch for Voice Mode** — Voice mode should be exclusive to the active voice session. If the user switches to a different session, that session must behave as a normal text-based chat mode. Fixed: voiceSessionId tracking with auto-disable on session switch.
- [x] **Beep sound timing** — The beep sound should trigger exactly when the state switches from listening to recording, rather than when the message is sent. Fixed in d3465d9c.
- [x] **Interrupted intermediate messages** — During the working phase, agent intermediate messages are being cut short (e.g., reading only a few words before stopping to perform a tool action like "search" or "grab"). Intermediate messages should be read in full without being interrupted by subsequent tool calls. Fixed: speakMessage() now queues naturally; speakFinalMessage() clears queue for final response.

## Features

- [x] **Background Voice Session & Floating Entry** — When voice mode is active, the session should continue working in the background. A floating button should appear on all other screens in the app, allowing the user to jump back into the active voice session and resume voice interaction. Fixed: background audio mode, pause/resume on lifecycle, VoiceFloatingButton overlay.
- [x] **UI Refactor: Minimalist Top Bar** — Remove most buttons from the top toolbar. The top bar should only contain a Settings (gear) icon and a Status/Stop button. Other controls (R-HIF, MCP, etc.) should be moved into a menu under the Settings icon. Fixed: consolidated into ellipsis.circle menu.
- [x] **Improved Agent Status Verbiage** — Refine the status text/voice cues used when an agent starts a task. Instead of always starting with "thinking", use more descriptive terms like "working on..." or "processing..." to better reflect the state after a message is sent. Fixed: workingStatusPhrase() uses last task prompt.
- [x] **Authentic Agent Icons** — Display the official logos for Claude Code, Gemini, and OpenCode next to the session title (under the tree) and as mini-icons next to the status in the important list. Board icons should remain unchanged. Fixed: AgentIcon draws brand-styled vector marks (Claude terracotta starburst, Gemini gradient sparkle, OpenCode terminal square); mini 12pt icons added next to StatusBadge in Important/Attention rows.
- [x] **Duplicate notifications for same session** — Socket reconnect + missed transition check both fire for the same running→idle transition. Fixed with `lastNotifiedStatus` tracking per session + stable notification ID (`session-{id}-idle` instead of timestamp-based). Clears on next running transition.
- [x] **No links or images in chat messages** — Three issues fixed:
  1. `.blocks` messages (most assistant messages) used plain `TextBlockView` instead of `EnhancedTextBlockView` — no file links, no session links, no inline images. Fixed `MessageContentView` to use `EnhancedTextBlockView` with all props.
  2. Markdown URLs not tappable — `StructuredText(markdown:)` rendered links but had no tap handler. Added `.environment(\.openURL, ...)` to `MarkdownTextView`.
  3. File path detection improvements — `FilePathDetector` now resolves bare filenames (e.g. `TODO.md`) against cached file list when unambiguous (exactly one match). Excludes matches inside URLs and domain TLDs. File list preloaded on session open.
- [x] **Scroll flickering and permission positioning** — Three fixes: (1) Added scrollToMessageInProgress coordination flag to prevent competing scroll animations, (2) Changed firstPendingPermissionId to currentPendingPermissionId using reverse iteration to scroll to most recent pending request instead of first, (3) Added lastResolvedPermissionTime tracking to restore userIsNearBottom after permission approval/denial within 2-5s window for contextual auto-scroll restoration.
- [x] **Cannot scroll to last message** — Bottom marker was only 1pt height with no padding, causing last message to be clipped by input bar. Fixed by increasing bottom spacer to 60pt to ensure last message scrolls fully into view above input bar.
- [x] **Input bar button sizing inconsistent** — Clipboard and mic buttons were 28×28pt but send button used 36pt icon with no frame constraint, making it oversized. Fixed send button to use 28×28pt frame matching other buttons for consistent visual alignment.
- [x] **Keychain autofill not working on login page** — iOS keychain offers autofill but password field stays empty. `ConnectionSetupView` doesn't load saved credentials from keychain. Fixed: added `.task` modifier to pre-populate `daemonURL` and `email` from `KeychainHelper.load()` on view appear.
- [x] **Server URL not remembered between sessions** — Daemon URL resets to empty string on each login. Same root cause as above — fixed by the same `.task` modifier loading URL from keychain.
- [x] **Random logouts (possibly after device reboot)** — Keychain items were missing `kSecAttrAccessible` attribute so they became inaccessible after reboot before first unlock. Fixed `KeychainHelper.save()` to always set `kSecAttrAccessibleAfterFirstUnlock`.
- [x] **Token expiry zombie state** — On startup, app gets 401 on `/users`, attempts token refresh which also returns 401 ("No access token"), logs the error, then continues as if authenticated. Socket auth also fails silently with expired token (no "Socket connected" log). App is in zombie state — shows chat UI but no messages arrive, file browser shows "Not authenticated". Fixed by adding `connect_error`/`.error` socket event handlers that detect 401 responses and call `authService.softLogout()` (clears tokens but keeps URL/email for re-login form pre-fill).
- [x] **Chat polling timer never fires (no streaming/messages when socket dead)** — `startMessagePolling()` and `startHealthCheck()` were called from inside `Task { }` which runs on Swift's cooperative thread pool. Those threads have no RunLoop, so `Timer.scheduledTimer` never fires — both the 10-second polling loop and health check timer were silently broken. Fixed by wrapping both timer creations in `DispatchQueue.main.async` to schedule on the main RunLoop.
- [x] **File browser "Not authenticated" on first open** — `FileBrowserViewModel.loadFiles()` is called on `ChatView.onAppear` before socket finishes connecting. Socket connects asynchronously (1-2s), so the file list request fails immediately with "Not authenticated". Fixed by adding `onChange(of: viewModel.connectionState)` in `ChatView` to retry `loadFiles()` when socket reaches `.connected` state and files are still empty.
- [x] **"Open in app" from file view** — File view should offer an "Open in app" action that hands the file to the system share/open-in flow so it can be opened in another installed app. Fixed: toolbar menu "Open in app…" writes the file to temp with its real name and presents UIActivityViewController.
- [x] **Per-file default "open in app" setting** — Optionally allow a setting per file (or per file type) that makes it open directly in the chosen external app instead of the in-app viewer. Fixed: per-extension "Always open .ext externally" toggle in the file-view menu; matching files auto-present the open-in sheet on load.
- [x] **PDF preview** — Render PDFs inline in the file view instead of requiring an external app. Fixed: PDFKit PDFView (continuous vertical, auto-scale) for base64 .pdf content.
- [x] **Hide Running and Favorites sections when filtering by board** — When a board filter is active, the Running and Favorites sections should be hidden so only the board's sessions are shown. Fixed: sections gated on selectedBoardId == nil.
- [x] **Background session status refresh + notifications** — While the app is in the background, refresh session status every 5 minutes and post a notification on status changes. Fixed root cause: previousSessionStatuses was memory-only, so BGAppRefresh cold launches could never see running→idle transitions — now persisted to UserDefaults; refresh chain also re-armed on every launch. Note: iOS decides actual BGAppRefresh timing (5 min is the minimum request, not a guarantee).
- [x] **Hold-to-speak voice input.** Fixed: hold the mic 1s → beep + haptic, records until release, transcribes once, appends to the prompt field without clearing existing text. Own DictationService, no VAD/TTS/turn-taking — the hold is the endpointing. Gesture is a single DragGesture(minimumDistance: 0); the earlier LongPressGesture.sequenced(before: DragGesture) spelling dropped touches. Tap-vs-hold is decided by elapsed time, not recorder state, so releasing at the threshold can't both enable voice mode and leave a recording running.
- [x] **Model preloading.** Fixed: Whisper preloads in the background on every launch. Previously gated on a voiceUsedKey flag, so a fresh install — the case preloading exists for — never preloaded.
- [x] **Cache downloaded files by filename.** Fixed: FileContentCache stores binary payloads (chat thumbnails, in-app PDF/file previews, downloads) in the Caches directory keyed by server + worktree + path, expiring 3 days after write — dropped on read, swept at launch. Text files excluded: live worktree source changes constantly.
- [x] **Add file-menu action beside “Open in App” to clear cache and redownload.** Fixed: "Clear cache & redownload" in the file detail menu drops that file's FileContentCache entry and refetches.
- [x] **Cache finished task transcripts.** Fixed: MessageCache stores messages of tasks in a terminal state (completed/failed/timed out/stopped), keyed by server + task id, 30-day sweep. Cached on fetch only — running tasks always hit the server, and a just-failed task still refetches so the executor's error message isn't missed.
- [x] **Opening a file re-scanned the whole worktree.** Fixed: the file list is fetched once per worktree instead of on every browser open (FileBrowserView.task called loadFiles() unconditionally; hasLoadedOnce was set but never read), pull-to-refresh forces a fresh scan, and a sheet opened straight onto a file from a chat link downloads that file before the tree scan starts.
- [x] **"Clear cache & redownload" did not update the view.** Fixed: the decoded image is view state, not part of fileDetail — it is now cleared and re-decoded after the refetch instead of only on file change.
- [x] **Never list the worktree just to open one file.** Fixed: opening a session no longer preloads the file list, opening a file from a chat link fetches that path directly over HTTP and skips the scan entirely, and chat thumbnails fetch over HTTP (gzipped, off the shared socket) instead of the socket. The list is loaded only when the browser is shown as a list, or as a fallback when a direct fetch fails — then the path is resolved against the tree and retried once. Trade-off: bare filenames in messages (e.g. `TODO.md` with no directory) no longer auto-link, since that resolution needed the list; explicit paths still do.
- [x] **Refresh the file list when new messages arrive.** Fixed: a message can mention files the agent created seconds ago, and a path only renders as a link once it matches a known file — but the list is no longer preloaded on session open. Arriving messages now trigger one debounced scan (2s after the burst settles, at most one per 15s), so links in the newest message resolve without a scan per message.
- [x] **Wrong path resolution made files "not found" that the chat showed correctly.** Root cause: the detector's regex did not include a leading `/`, so an absolute path like `/Users/me/proj/AgorApp/out.png` was captured from its *second* component onward — `Users/me/proj/AgorApp/out.png` — which is not a valid worktree-relative path and could not be recovered. Resolution then fell back to a unique-basename lookup, which gave up entirely on common names (`index.ts`, `README.md`). Fixed: the leading slash is part of the match, and resolution now takes the longest trailing run of path components that identifies exactly one known file, so `src/api/index.ts` beats a coin flip between five `index.ts` files. The same resolver is used for the failed-fetch retry.
- [x] **Keep PDF viewer at current scroll position during normal viewing without touch.** Fixed: the PDFDocument was constructed inside a ViewBuilder, so every body evaluation handed PDFKitView a brand new document and PDFView reloaded from the top. It is now decoded once off the main thread into view state, rebuilt only when the file changes or is redownloaded.
- [x] **Token refresh did not reach the socket, and refreshes only happened after a 401.** Fixed: refreshes now happen before the token expires (any request inside 60s of expiry renews first, coalesced with the existing in-flight refresh) rather than paying a wasted 401 round trip — which matters most for transports that cannot retry, like uploads and the socket. A successful refresh now also re-authenticates the socket: it had authenticated with the previous token and the server keeps the connection bound to it, so it went quiet while HTTP kept working. A 401 that survives a refresh is logged with the response body and the new token's remaining lifetime, which was previously invisible.
- [x] **File upload / attach was broken for every file.** Root cause: the app requested `?destination=branch`, but the daemon validates that query value against `worktree | temp | global` and fails the request in multer's destination callback before a byte is written — "branch" is the newer name for a worktree everywhere except here. Now sends `worktree`. Upload also bypassed the shared request path entirely, so it had no token refresh, no 401 retry, the default 30s timeout (a photo on a phone link surfaces that as URLError -1001), and no logging of the server's error body. All four fixed.
- [x] **Invalidate cached files that a newly arrived message mentions.** Fixed: an agent that just described a file has usually just written it, so those paths are dropped from FileContentCache the moment the message arrives. Driven by the socket "messages created" event rather than by the transcript changing, so reopening a session or relaunching the app replays old messages without invalidating anything. Both the path as written and its resolved form are dropped, since the cache is keyed by exact path.
- [ ] **Per-message speak button** — Each assistant *text* message (not tool-use or tool-result blocks) gets a small inline speak button the user taps to have that message read. Done already: enabling voice mode no longer auto-reads the last message.
- [ ] Recognize Agor UI session URLs in messages and render same session-link treatment as other session messages.
- [ ] Make chat image-thumbnail downloads reliable and retry-safe; investigate failures and duplicate note/message content on retry, using bounded or sequential fetching only if excessive concurrency is confirmed as cause.
- [x] **Download chat image thumbnails sequentially rather than concurrently.** Fixed: InlineImageLoader chains fetches so one download is on the wire at a time, dedupes identical paths, and checks FileContentCache both before queueing and again when the queued turn starts. Queued downloads are not cancelled with the view, so scrolling past an image still lands it in the cache. Views retry once after a failure instead of showing a permanent placeholder. Thumbnails now fetch over HTTP rather than the socket.
- [ ] Fix file/image download failures reporting Apple URL loading error -1001 (request timed out), with reliable retry behavior.
- [ ] Make attachment/file transfers reliable based on evidence: refresh and propagate auth tokens before JWT expiry; decode percent-encoded, branch-relative paths and return 404 for missing files instead of 500; expose upload response/body decode errors; separate HTTP file transfers from realtime socket events; cancel, debounce, and paginate huge session refreshes; retry without duplicate attachments/messages.
